## 1. Executive Summary & Backend Gap Analysis

The storefront and admin dashboard have implemented the **BigCommerce Catalyst-Style Product Modifiers Engine** (9 UI control types) and connected it throughout the purchasing funnel (PLP &rarr; PDP &rarr; Bag &rarr; Checkout &rarr; Receipts &rarr; Admin).

While the frontend currently provides full resilience using optimistic local storage fallbacks, **the backend database and API layer must now implement the balance of endpoints and data models** to achieve true end-to-end cloud persistence.

### Key Functional Gaps in Backend
1. **Missing Modifier Tables / Relations:** The database does not yet persist `ProductModifierGroup` and `ProductModifierOption` records relationally.
2. **Missing Granular Admin Endpoints:** Endpoints under `/api/v1/admin/products/:id/modifiers` return `404 Not Found` or `401 Unauthorized` in production.
3. **Cart Item Customizations Missing in Cart Table:** `POST /api/v1/cart/items` does not store the incoming `modifiers` array, losing price deltas during cart merge or server reload.
4. **Order Item Customizations Missing in Order Table:** `POST /api/v1/checkout` and `POST /api/v1/orders` do not store customization details on `OrderItem` rows, meaning tailoring notes and dupattas are omitted from the fulfillment team's receipts.

## 2. Database Schema Specifications (Prisma / SQL / MongoDB)

### 2.1 Prisma ORM Schema

```prisma
// ==========================================
// 1. PRODUCT MODIFIER GROUPS
// ==========================================
enum ModifierType {
  DROPDOWN
  RADIO_BUTTONS
  RECTANGLE_LIST
  CHECKBOX
  SHORT_TEXT
  MULTI_LINE_TEXT
  NUMBERS_ONLY_TEXT
  DATE
  FILE_UPLOAD
}

model ProductModifierGroup {
  id           String                  @id @default(uuid())
  productId    String
  product      Product                 @relation(fields: [productId], references: [id], onDelete: Cascade)
  name         String                  // Internal label, e.g. "dupatta_style"
  displayName  String                  // Customer-facing label, e.g. "Dupatta Customization"
  type         ModifierType            @default(RECTANGLE_LIST)
  isRequired   Boolean                 @default(false)
  minSelection Int                     @default(0)
  maxSelection Int                     @default(1)
  defaultValue String?
  config       Json?                   // { placeholder, minLength, maxLength, minValue, maxValue, allowedExtensions }
  sortOrder    Int                     @default(0)
  options      ProductModifierOption[]
  createdAt    DateTime                @default(now())
  updatedAt    DateTime                @updatedAt

  @@index([productId])
}

// ==========================================
// 2. PRODUCT MODIFIER OPTIONS
// ==========================================
model ProductModifierOption {
  id              String               @id @default(uuid())
  modifierGroupId String
  modifierGroup   ProductModifierGroup @relation(fields: [modifierGroupId], references: [id], onDelete: Cascade)
  name            String               // e.g. "Heavy Zari Organza"
  priceDelta      Decimal              @default(0.00) @db.Decimal(10, 2) // e.g. +1200.00
  isDefault       Boolean              @default(false)
  sortOrder       Int                  @default(0)
  createdAt       DateTime             @default(now())
  updatedAt       DateTime             @updatedAt

  @@index([modifierGroupId])
}

// ==========================================
// 3. CART ITEM CUSTOMIZATIONS
// ==========================================
model CartItemModifier {
  id               String   @id @default(uuid())
  cartItemId       String
  cartItem         CartItem @relation(fields: [cartItemId], references: [id], onDelete: Cascade)
  modifierGroupId  String
  modifierOptionId String?
  textValue        String?
  fileUrl          String?
  createdAt        DateTime @default(now())

  @@index([cartItemId])
}

// ==========================================
// 4. ORDER ITEM CUSTOMIZATIONS (Permanent Audit Snapshot)
// ==========================================
model OrderItemModifier {
  id               String    @id @default(uuid())
  orderItemId      String
  orderItem        OrderItem @relation(fields: [orderItemId], references: [id], onDelete: Cascade)
  groupName        String    // Preserved group label
  groupDisplayName String?   // Customer-facing group label
  type             String?   // RECTANGLE_LIST, SHORT_TEXT, etc.
  optionName       String?   // Choice name (e.g. "Organza Dupatta")
  textValue        String?   // Custom text (e.g. "Happy Wedding")
  fileUrl          String?   // Sketch/Pattern URL
  priceDelta       Decimal   @default(0.00) @db.Decimal(10, 2)
  createdAt        DateTime  @default(now())

  @@index([orderItemId])
}
```

### 3.2. Customer Cart & Checkout Endpoints

#### Endpoint 7: Add Item to Cart (with Modifiers Support)
* **Method:** `POST`
* **Route:** `/api/v1/cart/items`
* **Headers:** `x-guest-cart-token: <uuid>` (or `Authorization: Bearer <token>`)
* **Request Body:**
```json
{
  "productId": "9c9c5101-2200-4125-8065-355504dbcc15",
  "variantId": "var_88301",
  "quantity": 1,
  "modifiers": [
    {
      "modifierGroupId": "modgrp_55110",
      "modifierOptionId": "opt_88201"
    },
    {
      "modifierGroupId": "modgrp_text_99",
      "textValue": "Bespoke monogram: 'K & S'"
    }
  ],
  "modifierOptionIds": ["opt_88201"]
}
```
* **Backend Validation Logic:**
  1. Verify `productId` and `variantId` exist and have available stock.
  2. For option-based modifiers, look up `ProductModifierOption` and retrieve authoritative `priceDelta`.
  3. Compute authoritative pricing:
     $$\text{unitPrice} = \text{variant.price} + \sum \text{modifierOption.priceDelta}$$
  4. If an existing cart line item exists with the **exact same variant AND identical modifier selections**, increment its quantity; otherwise, create a separate cart line item.
* **Response (200 OK):**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Item added to bag",
  "data": {
    "id": "cart_123",
    "itemCount": 1,
    "subtotal": 16499.00,
    "items": [
      {
        "id": "cart_item_001",
        "productId": "9c9c5101-2200-4125-8065-355504dbcc15",
        "variantId": "var_88301",
        "quantity": 1,
        "pricing": {
          "unitPrice": 14999.00,
          "modifierTotal": 1500.00,
          "lineTotal": 16499.00
        },
        "selectedModifiers": [
          {
            "id": "opt_88201",
            "groupName": "dupatta_style",
            "name": "Hand-Dyed Organza Silk",
            "priceDelta": 1500.00
          }
        ]
      }
    ]
  }
}
```

#### Endpoint 8: Place Order (Saving Customizations Permanently)
* **Method:** `POST`
* **Route:** `/api/v1/checkout` (or `/api/v1/orders`)
* **Headers:** `Authorization: Bearer <token>`, `Content-Type: application/json`
* **Request Body:**
```json
{
  "shippingAddressId": "addr_123",
  "paymentMethod": "RAZORPAY",
  "couponCode": "FESTIVE10",
  "customerNotes": "Please deliver before Friday evening"
}
```
* **Backend Invariant:**
  - When converting cart items into `OrderItem` rows, copy all `CartItemModifier` entries into the permanent `OrderItemModifier` table.
  - This ensures order receipts, packing slips, and tailor instructions remain uncorrupted even if merchants update or delete modifier options in the future.

## 4. Critical Backend Gotchas & Invariants

1. **Prisma Type Coercion (`findMany` Crashes):**
   - Query strings `req.query.limit` and `req.query.page` arrive as strings. Always parse them:
     ```typescript
     const limit = Math.min(100, Math.max(1, parseInt(req.query.limit as string, 10) || 20));
     const page = Math.max(1, parseInt(req.query.page as string, 10) || 1);
     ```
   - Omit `limit` if it is NaN to prevent Prisma from throwing an uncaught 500 exception.

2. **Sanitize `undefined` / `null` in URL Parameters:**
   - Controllers must validate URL params before passing them to queries:
     ```typescript
     if (!req.params.id || req.params.id === 'undefined' || req.params.id === 'null') {
       return res.status(400).json({ success: false, message: 'Invalid identifier in URL path' });
     }
     ```

3. **Server-Side Price Integrity:**
   - Never trust the total price sent from the client.
   - Always re-calculate: `Variant Price + sum(Option Price Deltas) - Coupon Discount + Shipping = Total`.

4. **Tax Policy (All-Inclusive):**
   - Garment prices are MRP/all-inclusive. Do not add supplementary GST on top at checkout.
