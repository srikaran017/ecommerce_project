## 2. Canonical 5-Step Order Progression

The backend translates internal fulfillment states (`PENDING`, `CONFIRMED`, `PROCESSING`, `PACKED`, `SHIPPED`, `OUT_FOR_DELIVERY`, `DELIVERED`, `CANCELLED`, `RETURN_REQUESTED`, `RETURNED`, `REFUNDED`) into a standardized 5-step visual progress bar:

| Step | Key | Step Title | Description | Active Backend Statuses |
|---|---|---|---|---|
| **1** | `ORDER_PLACED` | **Order Placed** | Order placed by customer and logged into system. | `PENDING` |
| **2** | `ORDER_CONFIRMED` | **Order Confirmed** | Order verified and sent to atelier for tailoring, finishing, and packaging. | `CONFIRMED`, `PROCESSING`, `PACKED` |
| **3** | `SHIPPED` | **Dispatched & In Transit** | Package dispatched with courier partner (displays courier partner name & AWB number). | `SHIPPED` |
| **4** | `OUT_FOR_DELIVERY` | **Out for Delivery** | Package arrived at local destination hub and courier agent is out for final delivery. | `OUT_FOR_DELIVERY` |
| **5** | `DELIVERED` | **Delivered** | Package successfully delivered to customer. | `DELIVERED` |

### Special States:
- **`isCancelled: true`** (`status: 'CANCELLED'`): Shows order cancellation banner with the recorded `cancelReason` and `cancelledAt` timestamp. `currentStep` is set to `0`.
- **`isReturn: true`** (`status: 'RETURN_REQUESTED'`, `'RETURNED'`, or `'REFUNDED'`): Highlights active return/refund progression.

## 3. Storefront (Client) Endpoints Reference

### 3.1 Public & Authenticated Order Tracking (Query & Direct URL)
- **Endpoints**:
  - `GET /orders/track` (Query Parameters)
  - `GET /orders/:orderNumber/track` (Path Parameter)
- **Authentication**: Optional (`optionalAuthenticate`).
  - **Logged-in Customer**: Passing `Authorization: Bearer <token>` automatically verifies ownership. No email or phone query parameter is needed!
  - **Guest / Unauthenticated Customer**: Provide either `email`, `phone`, or `emailOrPhone` to verify access.
- **Frontend Screen**: `/track-order` landing page, header "Track Order" link, or post-order link.

| Parameter | Type | Required for Guest? | Description |
|---|---|---|---|
| `orderNumber` | `String` | Yes (if using `/orders/track`) | Order number (e.g. `ORD-20261020-DX40`). In `/:orderNumber/track`, passed via URL path. |
| `email` | `String` | Optional | Customer email address associated with the order. |
| `phone` | `String` | Optional | Customer phone number associated with the order (matches last 10 digits). |
| `emailOrPhone` | `String` | Optional | Combined field matching either email or phone. |

### 3.2 Public Order Tracking via Form Submission (POST /orders/track)
- **Endpoint**: `POST /orders/track`
- **Request Body**:
```json
{
  "orderNumber": "ORD-20261020-DX40",
  "emailOrPhone": "priya@example.com"
}
```

## 4. Admin Panel APIs Reference (`/api/v1/admin/orders`)

- `GET /admin/orders/:id` — Get full order details with live tracking.
- `PATCH /admin/orders/:id/shipping` — Assign courier partner and tracking AWB.
- `POST /admin/orders/:id/checkpoints` — Add custom tracking checkpoint/progress update.
- `PATCH /admin/orders/:id/status` — Advance order status via state machine.
