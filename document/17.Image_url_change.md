# Image Upload & URL Specification Guide (Cloudinary Integration)

**Document Reference:** `document/17.Image_url_change.md`  
**Target Audience:** Frontend Engineers (React / Next.js / Mobile) & QA / API Testers  
**Base URL:** `http://localhost:5000/api/v1` (also supports alias `/api`)  
**Storage Engine:** Cloudinary (Zero local disk storage; held in memory buffer and streamed securely)

---

## 1. Architectural Rule: The "One Only" Mutual Exclusivity Policy

For every endpoint handling images across the platform, the client has **two valid options**:

- **Option A — File Upload (Cloudinary):** Attach the image file (`.jpg`, `.jpeg`, `.png`, `.webp`, `.gif`) via `multipart/form-data`. The backend automatically streams it directly to Cloudinary and saves the secure HTTPS URL.
- **Option B — Direct Image URL:** Pass a valid HTTPS image URL as a string (or an array of URLs for products). The backend validates and saves the URL directly.

### ⛔ Conflict Rule
If a request supplies **BOTH** an image file upload **AND** an image URL simultaneously, the backend immediately rejects the request with a **400 Bad Request** and error code `IMAGE_INPUT_CONFLICT`.

#### Standard Conflict Error Response (`400 Bad Request`)
```json
{
  "success": false,
  "message": "Conflicting image input: Please provide either an image file upload OR an image URL, not both.",
  "error": {
    "code": "IMAGE_INPUT_CONFLICT",
    "details": [
      {
        "field": "image",
        "message": "Cannot accept both an image file upload and imageUrl simultaneously. Please choose one."
      }
    ]
  }
}
```

## 3. Detailed Endpoint Specs

### 3.1 Categories
- **Endpoint:** `POST /api/v1/admin/categories` & `PUT /api/v1/admin/categories/:id`
- **Access:** Private (Admin with `categories:manage`)
- **Mode 1: Direct File Upload (`multipart/form-data`)**
  - Headers: `Authorization: Bearer <TOKEN>` (Do NOT manually set Content-Type)
  - Fields: `name`, `description`, `sortOrder`, `isFeatured`, `image` (Binary file). Do NOT send `imageUrl`.
- **Mode 2: External Image URL (`application/json`)**
  - Headers: `Content-Type: application/json`, `Authorization: Bearer <TOKEN>`
  - Body: `name`, `description`, `imageUrl`, `sortOrder`, `isFeatured`.

### 3.2 Products
#### A. Product Creation & Update (`POST /admin/products` & `PUT /admin/products/:id`)
- **Access:** Private (Admin with `products:write`)
- **Mode 1: Direct Multiple Files Upload (`multipart/form-data`)**
  - Fields: `name`, `categoryId`, `regularPrice`, `brand`, `stockQuantity`, `variants` (stringified JSON), `images` (Binary files, up to 10). Do NOT send `images` as URL array.
- **Mode 2: Array of Image URLs (`application/json`)**
  - Body: `name`, `categoryId`, `regularPrice`, `brand`, `images: [{ url, altText, isThumbnail, sortOrder }]`

#### B. Standalone Gallery Image Upload (`POST /api/v1/admin/products/:id/images`)
- **Access:** Private (Admin with `products:write`)
- **Mode 1: Upload Image Files (`multipart/form-data`)**
  - Fields: `images` (File), `altText`, `isThumbnail`, `variantId`
- **Mode 2: Pass Image URL (`application/json`)**
  - Body: `{ "url": "https://...", "altText": "...", "isThumbnail": false, "variantId": "..." }`

### 3.3 Curated Collections
- **Endpoint:** `POST /api/v1/admin/collections` & `PUT /api/v1/admin/collections/:id`
- **Access:** Private (Admin with `collections:manage`)
- **Mode 1:** `image` file via `multipart/form-data`
- **Mode 2:** `imageUrl` via JSON

### 3.4 Promotion Campaigns (Hero Banners)
- **Endpoint:** `POST /api/v1/admin/promotions` & `PUT /api/v1/admin/promotions/:id`
- **Access:** Private (Admin with `promotions:manage`)
- **Mode 1:** `backgroundImage` (or `banner`, `image`) file via `multipart/form-data`
- **Mode 2:** `backgroundImage` URL via JSON

### 3.5 Customer & Admin User Avatars
- **Customer Avatar:** `POST /api/v1/customer/account/avatar` or `PATCH /api/v1/customer/account`
  - Mode 1: `avatar` file via `multipart/form-data`
  - Mode 2: `avatarUrl` via JSON
- **Admin User Avatar:** `POST /api/v1/admin/users` & `PUT /admin/users/:id`
  - Mode 1: `avatar` file via `multipart/form-data`
  - Mode 2: `avatarUrl` via JSON
